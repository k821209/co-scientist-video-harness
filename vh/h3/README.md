# h3_scene — 경계 키프레임 체인으로 여러 조각짜리 영상 장면 만들기

MiniMax-H3(fl2v)로 5초짜리 조각을 여러 개 이어 한 장면을 만드는 파이프다. 2026-09-22~27
에 llm-serving 프로젝트에서 실제로 돌려 가며 만들었고, 상수는 전부 **사용자가 원본 청크
영상을 보고 직접 정한 값**이다. Scivo 에 정식으로 넘겼고, 2026-09-27 부터 `vh.h3` 로 산다.

---

## 1. 무엇을 푸는가

조각을 이어 붙일 때 앞 조각의 **생성된 마지막 프레임**을 다음 조각의 첫 프레임으로 넘기면
톤과 대비가 조각마다 누적된다. 실측: 5조각 체인에서 국소대비 58 → 71 → 79 → 85, 밝기 출렁임
폭 40.1. 다섯 번째 조각쯤이면 눈에 띄게 어둡고 쨍해진다.

**해법**: 경계를 생성 프레임이 아니라 **Krea2 로 그린 키프레임**으로 삼고, 그 한 장을 앞
조각의 last 이자 다음 조각의 first 로 **공유**한다.

    샷 프롬프트 i ─┬─→ (Krea) 경계 이미지 B_i+1 ──┐
                   └─────────────────────────────┼─→ H3 조각 i  (B_i → B_i+1)
    경계 이미지 B_i ─────────────────────────────┘

생성 프레임이 다음 조각으로 흐르지 않으므로 **누적 경로 자체가 없고**, 이음매 양쪽이 같은
그림이라 어긋날 수 없다. 실측: 국소대비 12.5~13.4로 평평, 이음매 프레임차 0.4~3.5.

경계 키프레임은 전부 **시작 이미지에서** 편집한다. 앞 결과를 물리면 그게 곧 누적 경로다.

## 2. 파일 네 개가 한 벌

| 파일 | 역할 |
|---|---|
| `h3_scene.py` | 오케스트레이터. 이 패키지의 얼굴. 서브커맨드 `boundaries` / `chunk` / `join` |
| `krea2_edit.py` | Krea2 Edit 호출 — 경계 키프레임을 그린다 |
| `h3_run.py` | ComfyUI 에 H3 워크플로를 제출한다 (i2v / fl2v, 스타일·터보 LoRA) |
| `_h3util.py` | PyAV 헬퍼. 검사 지표(sparkle / tailjump / motion), 톤 고정(gradelock), 이어붙이기(concat) |

`_h3util.py` 는 **컨테이너 안에서** 돈다(`docker exec`). 호스트엔 ffmpeg 도 PyAV 도 없다는
전제이고, `ensure_util()` 이 md5 를 비교해 복사한다.

`configs/` 에 실제로 돌린 씬 설정 셋이 있다 — `scene5.json`(카페, 5조각 23.5초),
`park.json`(공원 벤치, 3조각), `run.json`(달리며 찍는 셀프, 3조각). 프롬프트 규칙은
글보다 이 예시로 읽는 게 빠르다.

## 3. 에이전트와 스크립트의 경계 — 여기가 설계의 핵심

**스크립트는 MCP 에 접근할 수 없다.** 원격 GPU 머신에서 돌기 때문이다. 그래서 "행이 기준"
원칙(사용자가 GO 를 켠 시점에 Video 탭 행에 들어 있는 파일이 유일한 진실)을 스크립트 안에
넣을 수 없고, 역할을 이렇게 나눴다:

    에이전트                              스크립트
    ──────────────────────────────────    ────────────────────────────────
    boundaries 실행                  →    B_i 생성, ###JSON### 뒤에 매니페스트
    update_video_chunk(n, last_image=) ←
    사용자가 탭에서 GO
    get_video_chunk_image(n,"start") →
    chunk --n --first --last         →    받은 경로 그대로 생성, 결과 경로 반환
    add_video_chunk(local_path=)     ←
    join --parts                     →    이어붙인 파일 경로 반환
    join_video_chunks(local_path=)   ←

행 번호 `n` 은 탭과 같은 1-based, 내부 조각 `i` 는 0-based (n = i + 1).

### 스크립트가 만드는 파일도 입력에 대해 결정적이다

Krea 가 그리는 경계 파일은 `<out>_b<i>_<hash(시작 이미지 내용, 프롬프트, 시드, 비율)>.png`
이다. 같은 입력이면 재사용하고(키프레임 30초를 다시 안 뽑음), 입력이 하나라도 다르면 이름이
달라서 옛 그림이 들어올 수 없다. `<out>_b<i>.png` 로만 지었을 때 같은 `--out` 의 다른 씬이
만든 8장을 종료 코드 0 으로 조용히 재사용했다(2026-09-27).

### 스크립트가 경로를 조립하지 않는다

이전 버전은 `f"{out}_b{n}.png"` 로 경계 파일명을 조립했다. 그게 어긋남의 근원이었다 —
`_v2` 가 생기거나 앞 조각을 다시 뽑아 **실제 마지막 프레임이 키프레임과 달라진** 순간,
이름만 보고 집으면 틀린 그림으로 4~5분을 태운다.

지금은 바깥에서 받은 이미지를 `stage()` 가 **내용 해시 이름**(`staged_<md5>.png`)으로
들여놓는다. 조각 번호나 씬 이름으로 지으면 서로 다른 그림이 같은 이름을 갖는 사고가
가능하지만, 해시면 그 사고가 성립하지 않는다 — 같은 이름은 항상 같은 그림이다.

## 4. 씬을 쓸 때 지킬 것 (전부 실측)

1. **한 조각에 큰 동작 하나.** 통과율: 3동작 6회 중 2회 · 2동작 6회 중 3회 · **1동작 7회 중 5회**.
   표정·손 정도는 같이 넣어도 된다.
2. **경계는 정지 자세가 아니라 동작 중간**으로(컵이 입가에 닿은 순간 등). 정지 자세로 잡으면
   이음매마다 멈췄다 다시 시작한다.
3. **입을 쓰는 동작이 있는 조각엔 대사를 넣지 않는다.** H3 는 조각 전체에 오디오를 만들어서
   "마시기 + 대사"를 5초에 넣으면 마시는 중에 말이 나온다. 대사는 다음 조각으로.
4. 키프레임 지시는 **5초 안에 닿을 자세**로.
5. **Krea 는 소품 상태 변경이 약하다**("책을 덮는다"가 반영 안 됨). 소품이 바뀌어야 하는
   전환은 피한다.
6. **이동하는 씬은 경계마다 배경을 길의 다른 구간으로.** 네 장이 같은 지점이면 처음과 끝의
   배경이 같아야 하므로 모델이 전진을 포기하고 제자리 뛰기가 된다. 실측(달리기 씬): 프레임간
   중앙값이 배경을 벌린 뒤 0.31~0.88 → 4.7~6.3.
7. **배경 요소는 모든 경계에 넣거나 모두에서 뺀다.** 한 장에만 없으면 그 장에 닿기 위해
   지워진다 — 조깅하는 사람들이 f24~f96 에 나왔다가 f123 에서 전부 사라진 사례.
8. 손·팔 동작은 **"카메라 쪽으로 뻗지 않는다"**를 명시한다. 안 그러면 손을 따라 몸이 다가오고,
   같은 구도의 마지막 프레임에 닿으려 되돌아간다.
9. Krea 는 **'새로 그리기'에서 제외 지시를 무시하고 '편집'에서는 따른다.** 빼야 할 것이 있으면
   시작 이미지를 깨끗한 경계 한 장에서 편집해 만든다(실측: 셀카 팔 제거가 새로 그리기 3회
   연속 실패, 편집 3회 전부 성공).
10. 경계 자세 문구 끝에 `There is exactly one person in the frame.` 을 붙인다. 없으면 "이마를
    훔친다" 같은 지시에서 인물이 복제된다.

## 5. 자동 검사 — 기준값의 출처

전부 **사용자가 원본 청크 영상을 보고 직접 판단한 값**이다. 모델이 정한 게 아니다.

| 지표 | 기준 | 사용자 판단 |
|---|---|---|
| `sparkle` 밝은 점 비율 % | 0.8 | 0.16~0.27 "깨끗" · **0.61 "안 보임"** · 1.13 "심하다" |
| `tailjump` 뒤 40프레임 최대 프레임차 | 14.0 | 1~7 정상 · **12.5 "괜찮음"** · 16.1 "구리다/거슬린다" |
| `motion` 프레임간 중앙값 | 1.0 | 미만이면 **경고만** — 실제로 park 씬을 보고 "자연스럽다"고 한 적이 있어 자동 폐기하지 않는다 |

둘 중 하나라도 넘으면 시드를 밀어 재시도(기본 2회). 전부 미달이면 **제일 나은 것**을 쓴다
(마지막 것이 제일 나쁠 수 있어 최고점을 보관했다 되살린다).

고정 카메라·앉은 장면에서 정한 값이라 달리기·핸드헬드에서는 정상 동작을 오탐한다. 그런 씬은
설정에 `sparkle_max` / `tailjump_max` / `motion_min` 을 직접 준다(run.json 참고: tailjump 30,
motion 3.0).

**★검사 셋이 못 잡는 것이 있다**: '다가왔다 물러나는 움직임'과 '중간에 생겼다 사라지는 배경
요소'. 둘 다 세 검사를 통과한다. 이동하는 씬은 생성 후 **필름스트립(f0/f24/f48/f72/f96/f123)을
눈으로** 봐야 한다. 여기에 자동 검사를 하나 더 붙이는 게 다음 개선점이다.

## 6. 이음매

경계 양쪽이 같은 그림이라 **아무것도 안 하는 게 기본**(이음매 프레임차 0.6~3.5).

- `trim_settle auto` — 앞 조각 끝의 멈춤을 자른다. **큰 되돌림(25 이상)만** 자르고, 자른 뒤
  이음매가 나빠지면 자동 취소. 이 가드가 없을 때 16 정도의 작은 되돌림까지 잘라 11프레임을
  날렸고 이음매가 2.9 → 35.6 으로 벌어졌다.
- `trim_head auto` — 다음 조각 앞의 '아직 안 움직이는' 구간을 최대 8프레임 자른다. 12프레임을
  자르면 실제 동작이 잘려 이음매가 3.0 → 4.5.
- **크로스페이드는 쓰지 않는다.** 앞 조각의 움직이는 꼬리와 다음 조각의 정지한 앞부분을 섞어
  없던 차이를 만든다. 실측(158f): 0 → 2.9 / 4 → 6.7 / **8 → 31.2**.
- 검은 페이드도 쓰지 않는다. 이음매 프레임차 17.0/17.3 → 0.4/0.1, 최저 밝기 0.0(검은 화면) → 85.3.

## 7. 머신 설정 — 환경변수만, 하드코딩 없음 (vh 의 `VH_*` 관례)

| 변수 | 뜻 | 기본 |
|---|---|---|
| `VH_H3_HOME` | ComfyUI 가 읽고 쓰는 **호스트** 디렉터리 (`<HOME>/input`, `<HOME>/output`) | 필수 |
| `VH_H3_CONTAINER` | ComfyUI 를 돌리는 docker 컨테이너 이름. 비우면 **베어메탈** | 비움 |
| `VH_H3_COMFY_IN` / `VH_H3_COMFY_OUT` | 컨테이너가 보는 input/output 경로 (컨테이너일 때만) | `/opt/ComfyUI/input`, `/opt/ComfyUI/output` |
| `VH_H3_PYTHON` | `krea2_edit.py` / `h3_run.py` / 베어메탈 `_h3util.py` 를 돌릴 인터프리터 (requests, PIL, 베어메탈이면 PyAV) | 실행 중인 python |
| `VH_H3_COMFY_HOST` | ComfyUI API | `http://localhost:8189` |

컨테이너 모드에서 `_h3util.py` 는 `docker exec` 로 컨테이너 안에서 돌고(호스트에 PyAV 가
없다는 전제), 베어메탈에서는 `VH_H3_PYTHON` 으로 바로 돈다. 헬퍼 스크립트들은 이 파일 옆에
있으며 별도 `docs/` 디렉터리는 필요 없다.

이전 머신(2026-09-27 인계 시점)의 값은: `VH_H3_HOME=$HOME/SparkyUI-H3`,
`VH_H3_CONTAINER=comfyui-h3`, `VH_H3_PYTHON=<conda env>/bin/python3`. 이 조합으로 동작이
인계 전과 같아야 한다 — **환경변수 추출은 인계 뒤 Scivo 쪽에서 했고 GPU 머신에서 다시
돌려 본 것은 아니다.** 첫 실행 때 그 조합으로 한 번 확인할 것.

- `h3_run.py` 는 **H3 워크플로 JSON 을 내장**한다. 모델·노드 이름이 바뀌면 같이 바뀐다.
- 길이 제약: **124~362 프레임, 17 단위.** 124f(5.2초)가 기본이다 — 길수록 재생성이 잦다
  (실측: 124f 4/8 · 158f 1/4 · 175f 0/2 · 209f 1/3, 실패는 대부분 끝부분 디졸브이고 길수록
  커진다 124f 12~26 / 209f 41~55).

### 알려진 한계

- `tts_segments` 류의 단어 타임스탬프가 없다 — 자막을 구우려면 따로 전사해야 한다.
- ComfyUI 는 입력·시드가 같으면 **캐시를 돌려주고 파일을 안 쓴다.** 성공을 반환하는데 결과가
  없어서, 파일 부재를 감지해 시드를 밀어 비켜간다(`generate()` 안).
- Krea 는 매 호출이 30초, 조각 하나는 4~5분 + 재시도. 청크당 평균 1.6~3회 생성이다.
  그래서 경계 먼저 보여 주고 GO 를 받는 절차가 비용상 필수다.

## 8. 라이선스·출처

MiniMax-H3 와 Krea2 는 각자의 모델 라이선스를 따른다. 이 스크립트 자체는 llm-serving
프로젝트에서 작성한 것이고 제약을 걸지 않는다.

측정 기록은 Scivo 프로젝트 `llm-serving` 의 Runs 탭 `h3-chain-grade-drift` 분석과 Video 탭의
비교 영상들에 남아 있다.
